# 详细设计方案编写方法论

本文档提炼自「太航制度管理详细设计方案 v7.1.1」，定义了一套完整的**企业级软件详细设计方案编写方法论**。生成 SRS 时，该方案的设计思路可作为功能需求的补充参考，指导如何将需求转化为可落地的详细设计。

---

## 一、核心设计思维

### 1.1 从需求到设计的转化路径

```
需求规格说明书（SRS）             详细设计方案（Design Spec）
┌─────────────────────┐          ┌──────────────────────────┐
│ 描述「做什么」         │  转化   │ 描述「怎么做」              │
│ FR-XXX：功能需求       │ ──────▶│ 页面设计 + 数据说明         │
│ 业务规则               │         │ 流程步骤 + 待办事项         │
│ 角色权限概述           │         │ 完整权限矩阵 + 通用规则     │
└─────────────────────┘          └──────────────────────────┘
```

SRS 的第 3~8 章定义了"做什么"，详细设计方案则将每个功能需求细化为四个维度。

### 1.2 四维功能分析法

每个功能模块的详细设计必须覆盖以下四个维度：

```
        ┌──────────────┐
        │   页面设计     │
        │  UI布局/交互   │
        └──────┬───────┘
               │
    ┌──────────┼──────────┐
    │          │          │
    ▼          ▼          ▼
┌──────┐  ┌──────┐  ┌──────────┐
│数据说明│  │流程说明│  │ 待办事项  │
│字段定义│  │审批流转│  │ 触发时机  │
│校验规则│  │步骤节点│  │ 推送目标  │
└──────┘  └──────┘  └──────────┘
```

| 维度 | 说明 | SRS 对应部分 |
|------|------|-------------|
| **页面设计** | 主页面/添加页面/详情页/弹出选择页的布局和交互 | §8 用户界面设计 |
| **数据说明** | 表单字段清单（名称、类型、必填、校验规则、默认值） | §3 功能需求 — 业务规则 |
| **流程说明** | 审批流程图、步骤定义、处理方式、流程意见格式 | §3 功能需求 — 主流程 |
| **待办事项** | 流程推进后产生的待办任务、接收人、标题格式 | §3 功能需求 — 后置条件 |

## 二、通用规则体系

在 SRS 和详细设计方案中，应抽取通用的业务规则作为全系统基准，避免在每个模块中重复描述。本项目定义了以下通用规则类别：

### 2.1 数据规则

| 规则 | 说明 | SRS 映射 |
|------|------|----------|
| 必填标识 | 数据项左侧 `*` 表示必填 | §3 功能需求 — 业务规则 |
| 数据类型说明 | 统一字段类型定义（见下表） | §2 设计约束 |
| 唯一引用校验 | 同一数据在单张单据中仅可引用一次 | §3 功能需求 |
| 业务占用校验 | 数据被引用后，流程完成前不可被相同业务再次引用 | §3 功能需求 — 替代流程 |

### 2.2 密级规则

> 适用于涉密系统的安全控制。SRS 安全需求（§4.3）中对应 NFR-SEC 编号。

| 规则 | 说明 |
|------|------|
| 密级定义 | 使用系统统一通用代码定义密级（公开/内部/秘密/机密/绝密） |
| 表单密级过滤 | 表单密级范围根据申请人密级过滤（显示 ≤ 当前用户密级的数据） |
| 附件密级过滤 | 附件密级根据表单密级进行过滤 |
| 审批人密级校验 | 流程参与审批人员密级 ≥ 表单密级 |
| 弹窗数据密级 | 弹出页数据密级 ≤ 表单密级 |
| 提交校验 | 提交时校验表单/制度/人员/附件四级密级一致性 |

### 2.3 流程规则

| 规则 | 说明 | 适用范围 |
|------|------|----------|
| 步骤按钮 | 文本取流程图中步骤动词 | 所有审批流程 |
| 处理方式 | 多人处理默认为「任意」 | 并行审批节点 |
| 待办标题 | 默认为表单名称 | 所有待办 |
| 表单权限 | 默认仅开始步骤可编辑表单数据项 | 所有流程 |
| 流程意见格式 | `时间@@人员@@部门@@意见` | 所有流程意见框 |
| 流程选人 | 默认勾选 | 选择处理人 |
| 候选处理人 | 部门领导节点默认显示部门正副职 | 领导审批节点 |

### 2.4 主页面规则

| 规则 | 默认值 |
|------|--------|
| 超链接 | `表单编号` 字段默认设为超链接，点击进入详情 |
| 编辑权限 | 登录人 = 申请人 且 状态 = 拟稿 |
| 删除权限 | 登录人 = 申请人 且 状态 = 拟稿；或登录人具备全部流程权限 |
| 查询条件 | 默认包含 `表单编号`、`申请人`、`申请部门`、`申请日期`、`当前处理人`、`当前步骤` |

### 2.5 数据权限分级

三级数据权限模型，适用于任何企业管理类系统：

| 权限级别 | 范围 | 说明 |
|----------|------|------|
| **本人权限** | 登录人参与的全部表单 | 默认权限，可筛选流程状态 |
| **部门权限** | 登录人所在部门全体员工的全部表单 | 部门领导、室主任 |
| **全部权限** | 全系统全部数据 | 公司领导、系统管理员 |

> SRS 中角色权限矩阵（§3.N）应体现此三级数据权限模型。

### 2.6 日志生成规则

统一的操作日志记录格式：

```
操作类型 + ID + 编号 + 名称
```

示例：
- `【新增：ID：XXXXX； 编号：XDRW-2021-001； 名称：制度XXX】`
- `【修改：ID：XXXXX； 编号：XDRW-2021-001； 名称：制度XXX】`
- `【删除：ID：XXXXX； 编号：XDRW-2021-001； 名称：制度XXX】`

> SRS 审计日志需求（§3.N + §11 附录）中使用此格式作为日志字段规范。

## 三、页面设计规范

### 3.1 页面分类体系

详细设计方案中每个模块的页面分为以下类型：

| 页面类型 | 用途 | 包含内容 |
|----------|------|----------|
| **主页面** | 列表查询和操作入口 | 查询条件区 + 操作按钮区 + 数据表格 + 分页 |
| **添加页面** | 新增表单数据 | 表单字段布局 + 验证规则 + 弹出选择控件 |
| **详细页面** | 查看/编辑已有数据 | 与添加页共用布局，权限控制编辑/只读 |
| **弹出选择页** | 关联数据选择 | 筛选条件 + 数据表格 + 单选/多选 + 确认按钮 |
| **待办进入页** | 从待办事项直接进入 | 自动填充关联数据，不可修改已关联的关键字段 |

### 3.2 页面间数据流转

```
主页面 ──[添加]──▶ 添加页面 ──[提交]──▶ 触发流程 ──[审批通过]──▶ 生成待办
                      │                    │
                      ▼                    ▼
                弹出选择页            下一步骤处理人
              (选择关联数据)
```

## 四、数据项说明规范

### 4.1 数据项定义模板

每个表单的数据说明应使用以下标准表格：

| 序号 | 数据项名称 | 数据类型 | 必填 | 唯一 | 默认值 | 校验规则 | 来源/说明 |
|:----:|-----------|:------:|:----:|:----:|--------|----------|----------|
| 1 | 表单编号 | VARCHAR(32) | ✓ | ✓ | 自动生成 | 见编号规则 | 系统自动 |
| 2 | 任务名称 | VARCHAR(200) | ✓ | — | — | ≤200字 | 用户输入 |
| 3 | 责任部门 | VARCHAR(64) | ✓ | — | 登录人部门 | 部门选择器 | 弹出选择 |
| ... | ... | ... | ... | ... | ... | ... | ... |

### 4.2 数据过滤条件描述模板

弹出选择页的数据过滤使用统一描述格式：

```markdown
**数据过滤条件**:
1. 制度修订任务通知单中，修订任务的修订类型为「新增」和「修订」
2. 制度修订任务通知单中，修订任务的任务处置方式为「是」
3. 修订责任部门为申请人所在部门的数据
```

## 五、流程设计规范

### 5.1 流程描述模板

每个流程应包含以下三要素：

```markdown
**审批流程**:
节点1[处理人角色] → 节点2[处理人角色] → ... → 结束

**流程图**: (BPMN 图或文字链式描述)

**流程步骤**:
| 步骤 | 处理人 | 处理方式 | 可执行操作 | 表单权限 | 流程意见格式 |
|:----:|--------|----------|-----------|----------|-------------|
| 1 | 申请人 | 单人 | 提交/保存/删除 | 可编辑 | — |
| 2 | 部门领导 | 多人任意 | 通过/驳回/转办 | 只读 | 时间@@人员@@部门@@意见 |
| ... | ... | ... | ... | ... | ... |
```

### 5.2 流程按钮命名规则

- 流程步骤的按钮文字**取自流程图中的步骤动词**
- 正向流转使用正向动词（提交、通过、批准）
- 逆向流转使用反向动词（驳回、退回、终止）
- 特殊操作使用专有动词（转办、加签、撤回）

## 六、待办事项设计规范

### 6.1 待办生成规则

流程推进到某个节点时，自动生成待办事项推送给对应的处理人。

| 规则项 | 说明 |
|--------|------|
| 待办标题 | 默认使用表单名称作为标题 |
| 待办类型 | 与业务模块对应（如"制度审核申请""发文管理"） |
| 待办接收人 | 流程当前步骤的处理人 |
| 待办完成条件 | 处理人完成该步骤操作后，待办自动完成 |

### 6.2 待办入口设计

点击待办事项后，根据业务类型有不同的入口行为：

- **直接打开表单页**：查看并处理（适用于审批类待办）
- **弹出关联页面**：选择后续操作再进入（适用于多分支流转）

## 七、角色-权限设计规范

### 7.1 二维权限模型

```
        菜单权限                    数据权限
    ┌─────────────┐          ┌─────────────────┐
    │ 可见页面/菜单 │          │ 本人/部门/全部     │
    │ 可用功能按钮  │          │ 数据行级过滤       │
    └─────────────┘          └─────────────────┘
           │                          │
           └──────────┬───────────────┘
                      ▼
              ┌───────────────┐
              │  完整的 RBAC   │
              │  角色-权限矩阵 │
              └───────────────┘
```

### 7.2 角色-菜单权限矩阵

| 角色 | 公文管理 | 阅批件 | 会议管理 | 制度管理 | 督办任务 | 系统管理 |
|------|:------:|:-----:|:------:|:------:|:------:|:------:|
| 公司领导 | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| 部门领导 | — | ✓(本部门) | ✓ | ✓ | ✓ | — |
| 制度管理员 | — | — | — | ✓ | — | — |
| 普通员工 | — | — | ✓ | — | ✓ | — |

### 7.3 角色-数据权限矩阵

| 角色 | 数据权限级别 | 说明 |
|------|:----------:|------|
| 公司领导 | 全部 | 查看全系统数据 |
| 部门领导 | 部门 | 查看本部门及下属科室数据 |
| 室主任 | 部门（受限） | 查看本科室数据 |
| 普通员工 | 本人 | 仅查看自己参与的数据 |

## 八、编号规则设计

统一编号规则是系统数据治理的基础：

```
编号格式：{业务前缀}-{年份}-{流水号}
示例：XDRW-2021-001（制度修订任务通知单）
     ZDSQ-2021-001（制度修订申请）
     SXZD-2021-001（试行制度处置申请）
     ZDSH-2021-001（制度审核申请）
```

| 规则项 | 说明 |
|--------|------|
| 业务前缀 | 2-6 位大写字母，唯一标识业务类型 |
| 年份 | 4 位数字，取创建时间年份 |
| 流水号 | 3-4 位数字，按业务前缀 + 年份独立流水，每年重置 |

> 此编号规则应在 SRS §3 对应功能需求的业务规则中定义，并在 §11 附录中汇总所有编号前缀。

## 九、报表看板设计方法

### 9.1 看板分类

| 看板类型 | 用途 | 数据来源 |
|----------|------|----------|
| **状态看板** | 按流程状态统计展示各类单据数量 | 主业务表 |
| **进度看板** | 展示任务/流程的完成进度 | 任务表 + 流程表 |
| **到期看板** | 展示即将到期的任务或制度 | 截止时间字段 |
| **处置看板** | 流程结束后的处置方式统计 | 处置结果字段 |
| **年度汇编** | 年度数据汇总和分类统计 | 年度数据范围 |

### 9.2 看板数据项设计模板

```markdown
**看板名称**: 制度修订申请看板

**查询条件**: 申请日期范围（起止）

**展示数据**:
| 分类 | 待审核 | 审核中 | 已通过 | 已驳回 | 合计 |
|------|:------:|:------:|:------:|:------:|:----:|
| 新增 | 3 | 5 | 12 | 1 | 21 |
| 修订 | 2 | 8 | 20 | 3 | 33 |
| 废止 | 0 | 1 | 5 | 0 | 6 |
| 合计 | 5 | 14 | 37 | 4 | 60 |
```

## 十、与 SRS 的协同关系

### 10.1 SRS → 详细设计方案的转化规则

| SRS 章节 | 转化目标 | 转化方法 |
|----------|----------|----------|
| §3.1 用户认证 | 详细设计 — 通用规则 | 转为「数据规则」「密级规则」等全局约束 |
| §3.N 功能需求 | 详细设计 — 功能模块 | 每个 FR 扩展为四维描述（页面+数据+流程+待办） |
| §3.N 角色权限 | 详细设计 — 角色-权限矩阵 | 转化为二维权限表（菜单+数据） |
| §4.3 安全需求 | 详细设计 — 密级规则 | 转化为具体的密级过滤校验逻辑 |
| §8 用户界面 | 详细设计 — 页面设计 | 每个路由页面细化为主页/添加页/详情页/弹窗页 |
| §11 附录 — 错误码 | 详细设计 — 数据规则 | 转化为字段级校验规则和提示文案 |

### 10.2 写入 SRS 时的应用

当生成 SRS 时，可将此设计方案的思路应用到以下章节：

1. **§2.3 设计约束**：引用「通用规则」作为全局设计约束
2. **§3 功能需求 — 业务规则**：每个 FR 的业务规则参考「数据规则」「密级规则」
3. **§3 功能需求 — 主流程**：流程描述参考「流程规则」的标准格式
4. **§8 用户界面**：页面设计参考「主页面规则」「添加页规则」
5. **§11 附录**：编号规则汇总、日志格式标准、数据权限分级
