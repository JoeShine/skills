# 需求规格说明书生成器（SRS Generator）

## 概述

此技能用于生成符合企业级标准的软件需求规格说明书（Software Requirements Specification, SRS）。
生成的文档结构完整、格式规范，包含引言、总体描述、功能需求、非功能需求、技术架构、数据需求、接口需求、用户界面设计、项目实施、验收标准和附录等标准章节。

## 何时使用此技能

在以下场景中应触发此技能：

- 用户要求"写一份需求规格说明书"、"生成SRS文档"、"编写软件需求文档"
- 用户需要将产品功能列表或项目背景转化为正式的需求文档
- 用户提供项目描述并要求生成结构化需求文档
- 用户说"根据XX项目创建需求文档"

## 工作流程

### 步骤 1：收集信息

在开始编写之前，向用户收集以下关键信息（如用户未提供）：

1. **项目基本信息**：项目名称、简称、所属组织
2. **项目背景**：解决的痛点、建设目标
3. **系统范围**：包含哪些模块和功能，排除哪些
4. **目标用户**：用户角色和估算人数
5. **技术栈偏好**：前后端框架、数据库选型（MySQL / Oracle 11g / 达梦 DM8）、中间件选择
6. **数据库选型**：若用户未指定数据库，根据项目规模、合规要求、信创需求推荐合适的数据库：
   - **MySQL 8.0**：轻量级、开源免费，适合中小型项目和通用场景
   - **Oracle 11g**：企业级、功能强大，适合大型企业和金融/政务等对数据一致性要求极高的场景
   - **达梦 DM8**：国产信创数据库，兼容 Oracle 语法，适合信创合规场景
7. **特殊约束**：安全合规要求（如等保等级）、信创要求、部署环境限制

如果用户无法回答某些问题，根据项目类型给出合理建议并请用户确认。

### 步骤 2：参照模板生成文档

生成 SRS 时，严格遵循 `references/srs_template_guide.md` 中定义的规范和模板。
该参考文件包含完整的章节结构、编号体系、优先级标记规范、功能需求描述模板等。

**数据库适配**: 根据用户选定的数据库（MySQL / Oracle 11g / 达梦 DM8），加载 `references/database_guide.md` 获取：
- 字段类型映射表（VARCHAR2 vs VARCHAR、NUMBER vs BIGINT 等）
- DDL 语法差异（自增策略、分页写法）
- ORM 配置差异（方言、连接池选型、JDBC 驱动）
- 信创合规说明（达梦 DM8 场景）

关键规范要点：
- 所有功能需求使用 `FR-{模块缩写}-{序号}` 编号体系
- 非功能需求使用 `NFR-{类别缩写}-{序号}` 编号体系
- 每个功能需求标注 `[M]`/`[S]`/`[O]` 和 `P0`-`P3` 优先级
- 功能需求采用"描述 → 前置条件 → 主流程 → 替代流程 → 后置条件 → 业务规则"结构
- API 接口使用"方法 | 路径 | 功能 | 说明"表格格式
- 数据模型包含"表名 | 说明 | 主要字段"结构，字段类型需匹配所选数据库
- 根据数据库选型调整 DDL 语法（分页写法、自增策略、序列、索引类型等），参考 `references/srs_template_guide.md` 中的数据库选型指南

### 步骤 3：输出文档

生成的 SRS 文档应包含以下标准章节（根据项目实际需求可适当裁剪）：

| 章节 | 内容要点 |
|------|---------|
| 文档控制 | 版本历史表格 |
| 目录 | 锚点链接目录 |
| 1 引言 | 编写目的、项目背景、系统范围、术语、参考文档、约定 |
| 2 总体描述 | 用户角色、运行环境、设计约束、假设与依赖 |
| 3 功能需求 | 按模块分组的详细功能需求（含编号、流程、规则） |
| 4 非功能需求 | 性能、可靠性、安全、可扩展、可维护、可用性、兼容性 |
| 5 技术架构 | 架构原则、架构图、技术选型 |
| 6 数据需求 | 数据库表、实体关系、数据量估算、缓存策略 |
| 7 接口需求 | RESTful API 接口定义 |
| 8 用户界面设计 | 设计原则、布局、路由、组件（仅前端项目需要） |
| 9 项目实施 | 实施策略、分阶段计划、培训方案 |
| 10 验收标准 | 功能验收、性能验收、安全验收、兼容性验收 |
| 11 附录 | 状态机规则、枚举字典、错误码、定时任务等 |

### 步骤 4：审阅与调整

生成初稿后：
1. 提醒用户逐章审阅
2. 根据用户反馈调整内容
3. 确保所有编号、交叉引用一致
4. 确认漏掉的功能需求已补充

## 输出格式

文档以 Markdown 格式输出，写入 `/workspace/` 目录，文件名格式为 `{项目名称}-需求规格说明书.md`。

使用以下 Markdown 特性确保文档可读性：
- GitHub-flavored Markdown 表格
- 锚点链接目录
- 代码块（JSON、SQL、伪代码等）
- ASCII 架构图
- 引用块标注关键信息
- 任务列表标记优先级
