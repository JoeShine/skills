# 需求规格说明书（SRS）编写指南

本指南基于企业级软件需求规格说明书的最佳实践，定义了一套完整的 SRS 编写规范和章节模板。

**编写基准标准**:
- **IEEE 830-1998**《软件需求规格说明推荐实践》— 定义 SRS 八大质量特征（正确、无歧义、完整、一致、分级、可验证、可修改、可追踪）和编写方法论
- **GB/T 22239-2019**《信息安全技术 网络安全等级保护基本要求》— 等保二级安全需求基准（默认），用户可指定更高级别
- **阿里巴巴 Java 开发手册** — 代码规范、数据库建表规约、工程结构，影响 §2.3、§4.5、§5、§6
- **RESTful API 设计规范** — 接口命名、HTTP 方法语义、响应格式，影响 §5、§7、§11
- 完整标准映射与协同应用规则详见 `references/standards_guide.md`

---

## 文档整体结构

标准 SRS 应包含以下 11 个主要章节，可根据项目规模适当裁剪：

| 章节号 | 章节名称 | 必填 | 说明 |
|--------|---------|:----:|------|
| — | 文档控制 | 是 | 版本历史、修订记录表格 |
| — | 目录 | 是 | 自动生成的目录 |
| 1 | 引言 | 是 | 编写目的、项目背景、系统范围、术语定义、参考文档 |
| 2 | 总体描述 | 是 | 用户角色、运行环境、设计约束、假设与依赖 |
| 3 | 功能需求 | 是 | 按模块划分的详细功能需求，含编号、优先级、流程描述 |
| 4 | 非功能需求 | 是 | 性能、可靠性、安全、可扩展、可维护、可用性、兼容性 |
| 5 | 技术架构 | 是 | 架构原则、总体架构图、技术选型表 |
| 6 | 数据需求 | 是 | 数据库模型、实体关系、数据量估算、缓存策略 |
| 7 | 接口需求 | 是 | 各模块 API 接口定义（方法、路径、功能、说明） |
| 8 | 用户界面设计 | 条件 | 含设计原则、色彩系统、页面布局、路由表、UI组件 |
| 9 | 项目实施 | 是 | 实施策略、分阶段计划、培训方案、验收标准摘要 |
| 10 | 验收标准 | 是 | 功能验收、性能验收、安全验收、兼容性验收 |
| 11 | 附录 | 条件 | 状态机规则、枚举字典、字段映射、定时任务清单、错误码等 |

## 文档规范

### 编号体系

- **功能需求编号**: `FR-{模块缩写}-{序号}`，如 `FR-AUTH-001`、`FR-MTG-001`、`FR-TSK-001`
- **非功能需求编号**: `NFR-{类别缩写}-{序号}`，如 `NFR-PERF-001`、`NFR-SEC-001`
- **模块缩写建议**: AUTH（认证）、MTG（会议）、ACT（行动项）、TSK（任务）、DASH（看板）、NOTIF（通知）、SRCH（搜索）、SYNC（同步）、INT（集成）、RPA（自动化）、RPT（报表）、ADM（管理）

### 需求优先级标记

- `[M]` — Must（必须）：强制性需求，不满足则系统不可交付
- `[S]` — Should（应该）：推荐性需求，除非有充分理由方可偏离
- `[O]` — May（可以）：可选性需求，根据资源情况决定
- `P0` — 核心/阻塞性
- `P1` — 重要
- `P2` — 改善性
- `P3` — 锦上添花

### 功能需求描述模板

每个功能需求应包含：

```markdown
#### FR-XXX-NNN 功能名称 [优先级标记]

**描述**: 一句话描述功能。

**前置条件**: 触发该功能的前提条件。

**主流程**:
1. 步骤一
2. 步骤二
...

**替代流程**（可选）:
- 异常分支描述

**后置条件**: 功能完成后的系统状态。

**业务规则**:
- 规则一
- 规则二
```

### 状态机定义格式

```
状态集合: state_a(名称), state_b(名称), ...

合法转换:
  state_a → state_b: 转换条件说明
  state_b → state_c: 转换条件说明
```

## 各章节编写要点

### 文档控制

版本历史表格格式：

| 版本 | 日期 | 修订人 | 修订内容 |
|------|------|--------|---------|
| v0.1 | YYYY-MM-DD | 作者 | 初始版本 |

### 第1章 引言

必须包含：
1. **编写目的** — 明确本文档的读者和用途
2. **项目背景** — 痛点分析 + 建设目标
3. **系统范围** — 包含/不包含范围，分Phase说明
4. **定义、缩写与术语** — 术语表
5. **参考文档** — **固定包含 GB/T 22239-2019 和 IEEE 830-1998**，参见 `references/standards_guide.md` 的标准引用模板
6. **文档约定** — 优先级、标记含义，并声明遵循 IEEE 830

### 第2章 总体描述

- **用户角色表**: 角色标识 | 角色名称 | 描述 | 典型用户画像 | 估算人数
- **运行环境**: 硬件环境（服务器配置）、软件环境（技术栈版本）、网络环境
- **设计约束表**: 约束类别 | 约束内容
  - 代码规范约束：「代码须符合阿里巴巴 Java 开发手册」
  - 接口规范约束：「API 设计须遵循 RESTful 规范」
- **假设与依赖表**: 假设/依赖 | 描述 | 风险等级

### 第3章 功能需求

按功能模块划分子章节：
- 3.1 用户认证与管理
- 3.2 核心业务模块A
- 3.3 核心业务模块B
- ...
- 3.N 系统管理

每个模块下按 `FR-XXX-NNN` 格式列出功能需求，包含完整的主流程、替代流程和业务规则。

### 第4章 非功能需求

按类别分组：性能、可靠性、安全、可扩展性、可维护性、可用性、兼容性。每类使用表格形式：

| 编号 | 指标 | 目标值 | 度量条件/详情 |
|------|------|--------|-------------|

**安全需求（等保二级基准）**: 安全需求必须覆盖以下等保二级控制项，完整映射参见 `references/standards_guide.md`：
- NFR-SEC-001 身份鉴别（密码策略、锁定机制） [M]
- NFR-SEC-002 访问控制（RBAC、最小权限） [M]
- NFR-SEC-003 安全审计（操作日志、不可篡改） [M]
- NFR-SEC-004 通信保密（TLS、HttpOnly Cookie） [S]
- NFR-SEC-005 数据保密（密码加密存储、敏感字段脱敏） [M]
- NFR-SEC-006 数据备份恢复（全量备份、保留周期） [S]
- NFR-SEC-007 软件容错（输入校验、故障隔离） [S]

**可靠性需求**: 必须包含数据备份恢复（等保二级要求），标注备份频率、保留周期和 RTO。

### 第5章 技术架构

- **架构原则**: 列举核心架构原则
- **总体架构图**: ASCII 或 Mermaid 图
- **技术选型表**: 技术层 | 技术方案 | 版本 | 说明
- **数据库选型说明**: 根据 `references/database_guide.md` 中的对比表，为所选数据库生成合适的技术选型说明

#### 数据库选型核心规则

在技术选型表中生成数据库行时，根据用户指定的数据库采用不同写法：

**MySQL 8.0:**
| 技术层 | 技术方案 | 版本 | 说明 |
|--------|----------|------|------|
| 数据库 | MySQL | 8.0 | InnoDB 引擎，支持事务和外键 |
| ORM | MyBatis-Plus | 3.5+ | 简化 CRUD |
| 连接池 | HikariCP | — | Spring Boot 默认 |

**Oracle 11g:**
| 技术层 | 技术方案 | 版本 | 说明 |
|--------|----------|------|------|
| 数据库 | Oracle | 11g R2 | 企业级，支持 PL/SQL、物化视图、高级分区 |
| ORM | MyBatis-Plus | 3.5+ | 需配置 `oracle` 方言 |
| 连接池 | Druid | 1.2+ | 更好的 Oracle 连接监控和管理 |
| JDBC驱动 | ojdbc6 | 11.2.0.4 | 匹配 Oracle 11g |

**达梦 DM8:**
| 技术层 | 技术方案 | 版本 | 说明 |
|--------|----------|------|------|
| 数据库 | 达梦 DM8 | 8.x | 国产信创数据库，兼容 Oracle 语法，通过等保和信创认证 |
| ORM | MyBatis-Plus | 3.5+ | 需配置 `dm` 方言 |
| 连接池 | Druid | 1.2+ | 更好的达梦连接管理 |
| JDBC驱动 | DmJdbcDriver | — | 达梦官方 JDBC 驱动 |

> **注意**: 若项目涉及信创要求，应在 SRS 中明确标注数据库选型理由（如"满足信创目录要求"），并在设计约束中增加"信创合规"约束项。

### 第6章 数据需求

- 按分类列出核心表（表名 | 说明 | 主要字段），**字段类型须匹配所选数据库**
- **阿里巴巴手册建表规约**（详见 `references/standards_guide.md` §5.1.3）：
  - 表名：小写字母+下划线，`业务名_表作用`（如 `task_main`、`sys_user`）
  - 必备三字段：`id`(主键)、`create_time`、`update_time`
  - 布尔字段：`is_xxx` 命名、`TINYINT` 类型
  - 索引命名：`idx_表名_字段名`；唯一索引 `uk_字段名`
- 实体关系 ASCII 图
- 数据量估算
- 缓存策略表
- 数据库特定说明：
  - Oracle 场景：注明 SEQUENCE 序列名、表空间名称
  - 达梦场景：注明模式名（Schema）、是否启用 IDENTITY
  - MySQL 场景：注明引擎（InnoDB）和字符集（utf8mb4）
- 详细数据库差异参考 `references/database_guide.md`

### 第7章 接口需求

按模块列出 API，使用表格：

| 方法 | 路径 | 功能 | 说明 |
|------|------|------|------|

**RESTful 规范强制要求**（详见 `references/standards_guide.md` §5.2）：
- URL 资源名用**复数名词**：`/api/tasks`（非 `/api/task`）
- 层级关系用路径表示：`/api/meetings/{id}/actions`
- 动作用后缀：`/api/tasks/{id}/urge`、`/api/tasks/{id}/progress`
- HTTP 方法严格语义化：GET/查询 POST/创建 PUT/更新 DELETE/删除
- 列表接口统一分页参数：`page`、`size`，响应含 `total`/`pages`
- 统一响应格式：`{code: 0, message: "success", data: {...}}`
- 批量操作路径：`/api/xxx/batch`

### 第8章 用户界面设计

- 设计原则
- 设计系统（色彩、字体、间距、圆角、阴影）
- 页面布局架构（ASCII 树形图）
- 路由与功能对应表
- 全局 UI 组件
- 组件状态规范

### 第9章 项目实施

- 分阶段实施策略（含周期和时间表）
- 培训方案
- 验收标准摘要（简表，指向第10章）

### 第10章 验收标准

- 功能验收表（验收项 | 验收标准 | 优先级）— 每个 FR 必须有对应验收项
- 性能验收表（指标 | 验收标准 | 测试方法）
- 安全验收表 — **必须包含等保二级专项验收项**（身份鉴别、访问控制、安全审计、通信保密、数据备份、软件容错），模板参见 `references/standards_guide.md`
- 兼容性验收表

### 第11章 附录

常用附录内容：
- 状态计算规则与判定伪代码
- 代码/枚举规范
- 系统间字段映射
- 批量导入模板规范
- 数据库索引建议
- 定时任务清单
- 错误码清单
- 状态/类型/角色/通知枚举
- 迭代计划摘要

## 写作风格指南

1. 使用客观、精确的语言，避免模糊表述
2. 每个功能需求使用"主流程 → 替代流程 → 业务规则"三段式描述
3. 功能需求描述使用"应（shall）"句式（IEEE 830 要求），如"系统应验证用户密码复杂度"
4. **禁止使用模糊词汇**：可能、大概、约、较好、尽量、基本上、差不多（违反 IEEE 830 无歧义要求）
5. 表格优于段落，适用于对比性信息
6. ASCII 图表优于纯文字描述
7. 使用 `[M]`/`[S]`/`[O]` 和 `P0`-`P3` 标注优先级（满足 IEEE 830 分级要求）
8. 表单字段使用"字段名称 | 数据类型 | 必填 | 说明"四列表格
9. 所有外部接口标注方向（系统A → 系统B）和同步频率
10. 安全需求需具体到加密算法和版本号（满足等保二级可验证要求）
11. 性能指标需明确 P95/P99 百分位数
12. 每份文档需包含文档控制（版本历史）和目录
13. 每个功能需求在第 10 章必须有对应的验收标准（IEEE 830 可追踪性要求）
14. URL 路径须使用复数资源名和小写字母（RESTful 规范）
15. 数据表须含必备三字段 `id`/`create_time`/`update_time`（阿里巴巴手册）
