# 需求规格说明书（SRS）编写指南

本指南基于企业级软件需求规格说明书的最佳实践，定义了一套完整的 SRS 编写规范和章节模板。

---

## 文档整体结构

标准 SRS 应包含以下 11 个主要章节，可根据项目规模适当裁剪：

| 章节号 | 章节名称 | 必填 | 说明 |
|--------|---------|:----:|------|
| — | 文档控制 | 是 | 版本历史、修订记录表格 |
| — | 目录 | 是 | 自动生成的目录 |
| 1 | 引言 | 是 | 编写目的、项目背景、系统范围、术语定义、参考文档 |
| 2 | 总体描述 | 是 | 用户角色、运行环境、设计约束、假设与依赖 |
| 3 | 功能需求 | 是 | 按模块划分的详细功能需求，含编号、优先级、流程描述 |
| 4 | 非功能需求 | 是 | 性能、可靠性、安全、可扩展、可维护、可用性、兼容性 |
| 5 | 技术架构 | 是 | 架构原则、总体架构图、技术选型表 |
| 6 | 数据需求 | 是 | 数据库模型、实体关系、数据量估算、缓存策略 |
| 7 | 接口需求 | 是 | 各模块 API 接口定义（方法、路径、功能、说明） |
| 8 | 用户界面设计 | 条件 | 含设计原则、色彩系统、页面布局、路由表、UI组件 |
| 9 | 项目实施 | 是 | 实施策略、分阶段计划、培训方案、验收标准摘要 |
| 10 | 验收标准 | 是 | 功能验收、性能验收、安全验收、兼容性验收 |
| 11 | 附录 | 条件 | 状态机规则、枚举字典、字段映射、定时任务清单、错误码等 |

---

## 文档规范

### 编号体系

- **功能需求编号**: `FR-{模块缩写}-{序号}`，如 `FR-AUTH-001`、`FR-MTG-001`、`FR-TSK-001`
- **非功能需求编号**: `NFR-{类别缩写}-{序号}`，如 `NFR-PERF-001`、`NFR-SEC-001`
- **模块缩写建议**: AUTH（认证）、MTG（会议）、ACT（行动项）、TSK（任务）、DASH（看板）、NOTIF（通知）、SRCH（搜索）、SYNC（同步）、INT（集成）、RPA（自动化）、RPT（报表）、ADM（管理）

### 需求优先级标记

- `[M]` — Must（必须）：强制性需求，不满足则系统不可交付
- `[S]` — Should（应该）：推荐性需求，除非有充分理由方可偏离
- `[O]` — May（可以）：可选性需求，根据资源情况决定
- `P0` — 核心/阻塞性
- `P1` — 重要
- `P2` — 改善性
- `P3` — 锦上添花

### 功能需求描述模板

每个功能需求应包含：

```markdown
#### FR-XXX-NNN 功能名称 [优先级标记]

**描述**: 一句话描述功能。

**前置条件**: 触发该功能的前提条件。

**主流程**:
1. 步骤一
2. 步骤二
...

**替代流程**（可选）:
- 异常分支描述

**后置条件**: 功能完成后的系统状态。

**业务规则**:
- 规则一
- 规则二
```

### 状态机定义格式

```
状态集合: state_a(名称), state_b(名称), ...

合法转换:
  state_a → state_b: 转换条件说明
  state_b → state_c: 转换条件说明
```

## 各章节编写要点

### 文档控制

版本历史表格格式：

| 版本 | 日期 | 修订人 | 修订内容 |
|------|------|--------|---------|
| v0.1 | YYYY-MM-DD | 作者 | 初始版本 |

### 第1章 引言

必须包含：
1. **编写目的** — 明确本文档的读者和用途
2. **项目背景** — 痛点分析 + 建设目标
3. **系统范围** — 包含/不包含范围，分Phase说明
4. **定义、缩写与术语** — 术语表
5. **参考文档** — 编号+说明
6. **文档约定** — 优先级、标记含义

### 第2章 总体描述

- **用户角色表**: 角色标识 | 角色名称 | 描述 | 典型用户画像 | 估算人数
- **运行环境**: 硬件环境（服务器配置）、软件环境（技术栈版本）、网络环境
- **设计约束表**: 约束类别 | 约束内容
- **假设与依赖表**: 假设/依赖 | 描述 | 风险等级

### 第3章 功能需求

按功能模块划分子章节：
- 3.1 用户认证与管理
- 3.2 核心业务模块A
- 3.3 核心业务模块B
- ...
- 3.N 系统管理

每个模块下按 `FR-XXX-NNN` 格式列出功能需求，包含完整的主流程、替代流程和业务规则。

### 第4章 非功能需求

按类别分组：性能、可靠性、安全、可扩展性、可维护性、可用性、兼容性。每类使用表格形式：

| 编号 | 指标 | 目标值 | 度量条件/详情 |
|------|------|--------|-------------|

### 第5章 技术架构

- **架构原则**: 列举核心架构原则
- **总体架构图**: ASCII 或 Mermaid 图
- **技术选型表**: 技术层 | 技术方案 | 版本 | 说明

### 第6章 数据需求

- 按分类列出核心表（表名 | 说明 | 主要字段）
- 实体关系 ASCII 图
- 数据量估算
- 缓存策略表

### 第7章 接口需求

按模块列出 API，使用表格：

| 方法 | 路径 | 功能 | 说明 |
|------|------|------|------|

### 第8章 用户界面设计

- 设计原则
- 设计系统（色彩、字体、间距、圆角、阴影）
- 页面布局架构（ASCII 树形图）
- 路由与功能对应表
- 全局 UI 组件
- 组件状态规范

### 第9章 项目实施

- 分阶段实施策略（含周期和时间表）
- 培训方案
- 验收标准摘要（简表，指向第10章）

### 第10章 验收标准

- 功能验收表（验收项 | 验收标准 | 优先级）
- 性能验收表（指标 | 验收标准 | 测试方法）
- 安全验收表
- 兼容性验收表

### 第11章 附录

常用附录内容：
- 状态计算规则与判定伪代码
- 代码/枚举规范
- 系统间字段映射
- 批量导入模板规范
- 数据库索引建议
- 定时任务清单
- 错误码清单
- 状态/类型/角色/通知枚举
- 迭代计划摘要

---

## 写作风格指南

1. 使用客观、精确的语言，避免模糊表述
2. 每个功能需求使用"主流程 → 替代流程 → 业务规则"三段式描述
3. 表格优于段落，适用于对比性信息
4. ASCII 图表优于纯文字描述
5. 使用 `[M]`/`[S]`/`[O]` 和 `P0`-`P3` 标注优先级
6. 表单字段使用"字段名称 | 数据类型 | 必填 | 说明"四列表格
7. 所有外部接口标注方向（系统A → 系统B）和同步频率
8. 安全需求需具体到加密算法和版本号
9. 性能指标需明确 P95/P99 百分位数
10. 每份文档需包含文档控制（版本历史）和目录
